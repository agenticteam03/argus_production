## 2026-10-29 - CON-9: console error states and the manual re-check (ACR-0043)

Type: feature (frontend)
Who: conantkd (+ agent)
Context: the operator console board ([OPERATOR-CONSOLE](../../tasks/current/OPERATOR-CONSOLE.md)) asks for clear errors and a
manual re-check; behaviour in [argus-console-mockup-spec](../../tasks/current/argus-console-mockup-spec.md) §8. Stacked on
CON-5 (#407): it changes the same console components.

What changed (frontend and brain docs only; no protected path):

- `utils/consoleSession.js`: `analysisView` names each failure in words and marks the retryable ones: "Analysis is taking
  longer than expected" (analyzing more than `ANALYSIS_TIMEOUT_S` = 90 s after `settle_until`), the API's `message` ("Metrics
  not available yet"), and "Analysis unavailable: <error>" for a backend failure. `waiting` also counts down from
  `countdown_s`. `historyFailed` and `nextHistory` decide what a failed history read does: a network error or a 5xx keeps the
  last entries and sets `unavailable`; a 4xx changes nothing.
- `hooks/useConsole.js`: uses `nextHistory`, returns `historyUnavailable`, and `recheck` only when the adapter has
  `recheckConsoleAnalysis`.
- `ConsolePanel.jsx`: a "Console history unavailable, retrying" status line, and a Re-check button on a retryable analysis
  ("Re-check failed" when it fails). `OperatorConsole.jsx` ticks the clock while an analysis runs, for the timeout.
- Demo: `demoConsoleRecheck` and `mockArgusAdapter.recheckConsoleAnalysis` (POST `.../commands/{command_id}/recheck`, 409 when
  not retryable). `api errors`, `host metrics` and `worker throughput` reach the three failures. The http adapter gets no
  re-check call: the real route comes with the analysis wiring.
