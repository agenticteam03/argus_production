## Retrieval and integration

The supplied architecture retrieves Markdown through `KnowledgePort` from `argus/runbooks/`. This workspace's `runbooks/` is a separate authored corpus; no sibling implementation, retriever, detector, policy or deployment has been modified. Integrate through a reviewed corpus change and evaluate retrieval against labeled cases before production use.

**Compatibility blocker:** the inspected TF-IDF adapter takes the entire filename stem as `runbook_id`, splits at `##` and returns at most 1,600 characters per section. Map the metadata ID (for example `RB-001`) explicitly instead of treating the descriptive stem as the stable ID. Replace silent truncation with bounded coherent passages plus mandatory safety/verification context, or refuse incomplete action guidance. Copying these files into the current retriever unchanged does not satisfy that contract.

Preserve stable ID and version in retrieved passages. Always include scope, available-versus-missing tools, action constraints and verification alongside diagnostic/action passages. Pin the shared contracts as context or embed their relevant rules during indexing; a link alone is not evidence the LLM received them. Keep authoring/reference/backlog documents outside action-oriented retrieval unless deliberately typed as such. Never interpret a `MISSING TOOL REQUIREMENT` name as an available function.
